Before we install anything

OpenClaw is an agent you install, run, and own.

It's free, open-source software. It runs on your computer or a server you rent, and connects a model to your files, your tools and your chat apps.

🏠 It runs where you put it

Nobody hosts it for you. On your laptop, it sleeps when the laptop does; on a rented server, it runs around the clock.

🧠 Any model

Claude, GPT, Gemini, Kimi, or a model on your own machine. Switch with one command.

💬 It lives in your chat apps

Telegram, Slack, WhatsApp and more. You message it like a person.

⚖️

The trade: you can change everything, and you maintain everything. Updates, uptime, security and debugging are yours now, with Claude Code as your help desk.

Read this before anything runs

No per-run cap here: trim the overhead, cap the provider.

Managed Agents capped every run, but you couldn't touch the overhead that rides along with each call. OpenClaw flips both: there's no per-run budget field, so the limits move to your model provider, and the overhead is yours to cut.

📦 Overhead rides every call

Its instruction files, skill list and tool list go out with every message. The default install is full of extras. Step 1 cleans them out.

💓 The heartbeat

By default it wakes every 30 minutes: 48 times a day, and each wake can carry around 100,000 tokens. It stays off until you set it up lean.

🧾 The cap lives at the provider

A monthly limit, prepaid credits, auto-reload off, at each provider you use. Hosting bills separately.

🔑

The classic surprise bill is a key pushed to GitHub, where bots find it within minutes. Keys go in a .env file that's in .gitignore before your first commit.

Open the folder in VS Code and you're looking at the agent

Your agent is a folder of plain-text files.

No form to fill in: you, Claude Code, and the agent itself edit these files. The ones marked 📌 are loaded into every call.

AGENTS.md📌 Its operating rules: how it works, what's off-limits. The biggest file by default.
SOUL.md📌 Its personality and values.
USER.md📌 About you: role, time zone, what matters.
IDENTITY.md📌 Its name, vibe and emoji.
MEMORY.md📌 Long-term memory it curates. Only in your own chats.
memory/A dated note per day. Read when needed, not every call.
HEARTBEAT.mdThe checklist it follows each time the heartbeat wakes it.
TOOLS.mdNotes about your setup: device names, accounts.
BOOTSTRAP.md📌 A first-run interview. Delete it once it's done.
skills/Its skills, one folder each.

The model, channels, schedules and permissions live outside the folder, in ~/.openclaw/openclaw.json, along with its logins.

The engine room

The Gateway is the always-on program that runs everything.

⚙️ The Gateway

Runs in the background on your computer. Only your own machine can reach it, and it serves the Control UI, a dashboard you open with openclaw dashboard.

💬 Channels

The chat apps it listens on. Telegram comes built in. Slack, WhatsApp, Teams, Discord, Signal and iMessage are plugins you add.

🔐 Pairing

Anyone can find a bot. When a stranger messages it, they get a code, and nothing happens until you approve it.

😴

No Gateway, no agent. If your laptop is asleep at 7:30, the 7:30 run doesn't happen. That's what hosting it in the cloud solves, at the end of class.

What it can do, and what it's allowed to do

Tools act, skills teach, and permissions limit both.

🧰 Tools

Built in: run commands, read and write files, web search and fetch, a browser, send messages, schedule jobs.

📘 Skills

A folder with a SKILL.md, like your Class 4 skill. About 50 come bundled, and thousands more are on ClawHub, the skill store.

🚦 Permissions

Allow and deny lists for tools, and approvals for commands: deny, allowlist or full, with or without asking you. The stricter setting wins.

🐍

This is how a custom tool becomes real. Your Python script sits in the folder, a skill tells the agent when to run it, and the command tool runs it. No app of your own needed: the Class 5 limit is gone.

Managed Agents had a schedule and you. OpenClaw has four.

It wakes four ways: message, heartbeat, schedule, webhook.

💬 A message

You, in Slack, Telegram or any chat app you connect. It answers in the same chat.

💓 A heartbeat

A regular check-in: it reads HEARTBEAT.md and messages you only if something needs you. Handy, and a cost setting.

⏰ A schedule

An automation at exact times, like a deployment's cron. Each can run in its own clean session with its own model.

🪝 A webhook

Another app knocks on its door with a secret token: a new form response, a file landing, a payment. It wakes and handles it.

Rule of thumb: exact times go in a schedule; loose "keep an eye on things" goes in the heartbeat.

The one thing no Anthropic surface does

Switch models with one command, and set a fallback.

OpenClaw works with more than 60 providers: Anthropic, OpenAI, Google, xAI, Moonshot (Kimi), OpenRouter, and models running on your own machine. openclaw models set changes it; /model changes it mid-chat.

🎯 Fit the model to the job

A strong model for judgment calls, a cheap one for routine checks. The same idea as your chain, inside one agent.

🛟 A fallback

If the main model is down or rate-limited, it switches to the next one on your list.

🧪 Test before you trust

Models follow instructions differently. After a switch, test-run it and read what it did.

I run mine on Kimi. Each provider is its own account, its own bill and its own spend limit.

Nobody else is watching this one

You're the security team now.

🧩 Read every skill before you install it

In February 2026, researchers found 341 malicious skills on ClawHub that stole data from Macs. A skill is code with your access. Install only what you or Claude Code have read.

🔒 Keep the Gateway private

It only answers your own machine by default: keep it that way. openclaw security audit checks your setup.

🔑 Keys in .env, never in a chat

Not in the chat with Claude, not in the agent's files, not in GitHub.

⬆️ Keep it updated

Security fixes ship often. Early 2026 fixed a bug that let one bad link take over an install.

The Class 5 rules carry over: it drafts, you send, and anything it reads from strangers can try to give it orders.

Before Step 1 · in VS Code

Install OpenClaw, with your project folder as its home.

Make a folder called morning-agent, open it in VS Code, and paste this into Claude Code:

Install OpenClaw with the official installer from docs.openclaw.ai. Before anything else, make this folder a private GitHub repo with a .gitignore that excludes .env. Then tell me exactly how to run openclaw onboard myself in the VS Code terminal, using this folder as the workspace. When I'm done, run openclaw doctor and openclaw gateway status and explain the results.
⌨️ You run onboarding yourself

In the VS Code terminal, so your model key goes into the terminal, never into the chat. Pick ask first over full access, and your provider and model.

🙅 Say no to the extras

Skip the suggested skills and plugins, and the memory import. Each one adds overhead and risk. You add what you need later.

The control Managed Agents never gave you

Step 1: Clean it out before it costs you on every call.

Open the Control UI (openclaw dashboard) and send /context detail: it shows what every file and skill costs per call. Note the total. Then paste this into Claude Code:

Clean out my OpenClaw install to cut per-call overhead. Show me each change before you make it. 1) Delete BOOTSTRAP.md. 2) Cut AGENTS.md down to what a morning agent needs: remove group chats, emoji reactions, voice, platform formatting and the heartbeat examples; keep the memory rules and red lines. 3) Strip the boilerplate from SOUL.md and TOOLS.md. 4) In openclaw.json, turn off every bundled skill and turn the heartbeat off. 5) Restart the gateway and run openclaw doctor.
📉

Send /context detail again and compare. That difference is saved on every message, every schedule and every check-in, for as long as the agent runs.

Rebuild from the working agent, not a description

Step 2: Pull in your Class 5 agent and translate it.

Download handoff-log.md from your briefing folder into this folder. Then paste:

Use the ant CLI to download my Class 5 agent, [name], from the Claude Console into a class5-export folder. Rebuild it for OpenClaw: who I am goes in USER.md; its job, the three-section handoff it owes me and its limits go in AGENTS.md; its tone goes in SOUL.md; the standing notes from handoff-log.md go in MEMORY.md. Keep every file short. Then list the apps the Console agent reached through MCP servers, and how we'll reach each one here.
📂 The export is your blueprint

Model, system prompt, tools. Commit it: it's the record of the version that worked.

🔌 Logins don't come across

Your vault never leaves the Console, which is correct. Each app gets connected again here, one at a time.

The cost lever and the key rule

Step 3: Set the model, a fallback, and your .env file.

🧠 Models

Tell Claude Code: "Set my main model to [model] and add [model] as a fallback." The main model makes this agent's judgment calls, so don't go cheapest here. Routine jobs can get a cheaper model of their own later.

🔑 The .env file

Tell Claude Code: "Create .env and confirm it's in .gitignore." Then open .env in VS Code and paste each key there yourself. Your scripts read keys from it; Claude never sees them in the chat.

✅

Check before every commit: ask Claude "Is anything secret about to be committed?" One habit, and the classic surprise bill can't happen.

The thing Managed Agents couldn't do

Step 4: Connect the chat app you already live in.

  • 1. Pick one. Telegram comes built in. Slack, WhatsApp, Microsoft Teams, Discord, Signal and iMessage are official plugins, and there are more.
  • 2. Tell Claude Code: "Connect OpenClaw to [app]. Walk me through creating its bot, put any token in .env, and keep DMs on pairing."
  • 3. Message your bot. It replies with a pairing code. Tell Claude Code: "Approve pairing code [code]."
  • 4. Send it a job: "What's on my calendar tomorrow?" Then check the answer is real.
💼

Slack at work usually needs an admin to approve a new app. If that approval won't come today, start with Telegram, which only needs you, and add Slack when it does.

Branching, hands-on

Step 5: On a branch, give it a Python script as a tool.

main is the agent that runs. A branch is a copy where you change things safely; nothing touches main until it's reviewed. Paste:

Create a branch called add-brief-tool. On it, write a Python script in scripts/ that finds today's morning brief in my [Drive / Dropbox] briefing folder and prints its text, reading its key from .env. Then write a skill that tells the agent to run this script first when it handles my morning. Test it, commit it on the branch, and don't merge.
🐍 The script does the fetching

Same result every run, for almost nothing. The agent spends its tokens on the judgment, not on finding a file.

📘 The skill says when

Without the skill, the agent doesn't know the script exists. Together, they're a custom tool.

The author shouldn't grade its own work

Step 6: A second AI reviews the branch, then you merge.

  • 1. Tell Claude Code: "Open a pull request for add-brief-tool." That's the proposal to change main.
  • 2. Open Codex (or another AI) in VS Code: "Review this pull request for bugs and security problems, especially how it handles keys."
  • 3. Paste the findings to Claude Code: "Fix what's real, and tell me what you disagree with."
  • 4. "Merge it into main and restart the gateway." Then message the agent: "Handle my morning."
🌿

Every change from now on goes this way: branch, review, merge. When the agent runs in the cloud, main is what runs, so only reviewed code ever reaches it.

Your deployment, rebuilt

Step 7: Schedule the 7:30 run, and decide on the heartbeat.

Create an OpenClaw automation: weekdays at 7:30 in my time zone, in its own session, with the prompt "Handle my morning." Save the handoff to my briefing folder and send it to me in my chat app. Then show me the next five run times.
💓 The heartbeat stays off for now

When you want check-ins, turn it on with a short HEARTBEAT.md, its own light session, and working hours only. That keeps each wake to a few thousand tokens.

✌️ Two agents, one brief

Your Class 5 deployment also runs at 7:30. Two agents working one brief means double drafts: once this one's handoff is right, pause one of them.

The chain now crosses surfaces: the brief still runs in Managed Agents at 7:00, and OpenClaw picks it up. Each link lives wherever suits it.

Outside events that wake it

A webhook lets another app wake your agent.

You turn on OpenClaw's hooks and it gets an address. Any app that can send a web request can knock on it, with a secret token, and the agent handles what arrives.

📝 A form is submitted

A new brief request from a client: it drafts the kickoff notes.

📂 A file lands

The Class 4 brief is saved: it starts right away instead of waiting for 7:30.

⚡ A Zap fires

Anything Zapier or Make can see becomes something your agent can act on.

🌍

Webhooks need an address the internet can reach, and your laptop isn't one. They come with cloud hosting, and the token is a key: it goes in .env.

There's no Sessions page doing this for you

When it breaks, you and Claude Code are the support team.

🩺 Health

openclaw status shows channels, sessions and usage. openclaw doctor finds broken config, and --fix repairs it.

📜 What happened

openclaw logs --follow streams the log. The Control UI keeps each session's transcript, like Sessions in the Console.

🔍

Describe the symptom and let Claude Code dig: "My 7:30 run didn't come. Check OpenClaw's status and logs and tell me why." Then fix the cause on a branch, like any other change.

Explained today, done when you're ready

Render runs your agent from GitHub, laptop open or not.

Render is a hosting service, and OpenClaw's docs include a setup for it. You connect your GitHub repo, and Render runs the agent around the clock.

🌿 It runs main

Every merge to main redeploys it. That's why every change goes through a branch and a review first.

💾 Pay for a disk

On the free plan, the agent's memory is wiped on every deploy. A paid plan with a disk keeps it.

🔑 Keys go in Render

In Render's environment settings, never in the repo. And it's one more bill to cap.

Once it's in the cloud, it can take webhooks, and 7:30 runs whether your laptop is open or not.

Your homework

Finish the agent until its handoff matches Class 5's.

🔌 Connect every app it needs

One at a time, each on its own branch: a plugin or skill if a trusted one exists, otherwise a script tool.

💼 Add a second chat app

Slack at work once your admin approves it, or any other app you'd rather message it from.

📉 Watch the cost for a week

Check each provider's usage daily. Trim anything that grew back.

☁️ Then decide

Move it to Render, or go back to Class 5 if that did the job. Either is the right call.
