Before we install anything

OpenClaw is an agent you install, run, and own.

It's free, open-source software. It runs on your computer or a server you rent, and connects a model to your files, your tools and your chat apps.

🏠 It runs where you put it

Nobody hosts it for you. On your laptop, it sleeps when the laptop does; on a rented server, it runs around the clock.

🧠 Any model

Claude, GPT, Gemini, Kimi, or a model on your own machine. Switch with one command.

💬 It lives in your chat apps

Telegram, Slack, WhatsApp and more. You message it like a person.

⚖️

The trade: you can change everything, and you maintain everything. Updates, uptime, security and debugging are yours now, with Claude Code as your help desk.

Read this before anything runs

No per-run cap here: trim the overhead, cap the provider.

Managed Agents capped every run, but you couldn't touch the overhead that rides along with each call. OpenClaw flips both: there's no per-run budget field, so the limits move to your model provider, and the overhead is yours to cut.

📦 Overhead rides every call

Its instruction files, skill list and tool list go out with every message. The default install is full of extras. Step 1 cleans them out.

💓 The heartbeat

By default it wakes every 30 minutes, 48 times a day, and resends your whole chat history each time. The longer the chat, the more each wake costs. It stays off until you set it up lean.

🧾 The cap lives at the provider

A monthly limit, prepaid credits, auto-reload off, at each provider you use. Hosting bills separately.

🔑

A leaked key is a blank check: anyone who has it can run models on your bill. The usual leak is a key uploaded to GitHub by accident. So keys live in one file, .env, and Git is told never to upload it.

Open the folder in VS Code and you're looking at the agent

Your agent is a folder of plain-text files.

No form to fill in: you, Claude Code, and the agent itself edit these files. The ones marked 📌 are loaded into every call.

AGENTS.md📌 Its operating rules: how it works, what's off-limits. The biggest file by default.
SOUL.md📌 Its personality and values.
USER.md📌 About you: role, time zone, what matters.
IDENTITY.md📌 Its name, vibe and emoji.
MEMORY.md📌 Long-term memory it curates. Only in your own chats.
memory/A dated note per day. Read when needed, not every call.
HEARTBEAT.mdThe checklist it follows each time the heartbeat wakes it.
TOOLS.mdNotes about your setup: device names, accounts.
BOOTSTRAP.md📌 A first-run interview some setups create. Delete it once it's done.
skills/Its skills, one folder each.

The model, channels, schedules and permissions live outside the folder, in ~/.openclaw/openclaw.json, along with its logins.

The engine room

The Gateway is the always-on program that runs everything.

⚙️ The Gateway

Runs in the background on your computer. Only your own machine can reach it, and it serves the Control UI, a dashboard you open by running openclaw dashboard in a new VS Code terminal.

💬 Channels

The chat apps it listens on. Telegram comes built in. Slack, WhatsApp, Teams, Discord, Signal and iMessage are plugins you add.

🔐 Pairing

Anyone can find a bot. When a stranger messages it, they get a code, and nothing happens until you approve it.

😴

No Gateway, no agent. If your laptop is asleep at 7:30, the 7:30 run doesn't happen. That's what hosting it in the cloud solves, at the end of class.

What it can do, and what it's allowed to do

Tools act, skills teach, and permissions limit both.

🧰 Tools

Built in: run commands, read and write files, web search and fetch, a browser, send messages, schedule jobs.

📘 Skills

A folder with a SKILL.md, like your Class 4 skill. About 50 come bundled, and thousands more are on ClawHub, the skill store.

🚦 Permissions

Allow and deny lists for tools, and approvals for commands: deny, allowlist or full, with or without asking you. The stricter setting wins.

🐍

This is how a custom tool becomes real. You register your Python script as a tool, with a name, a description and inputs, through a small local MCP server. The agent sees it in its tool list like any other. No app of your own needed: the Class 5 limit is gone.

Managed Agents had a schedule and you. OpenClaw has four.

It wakes four ways: message, heartbeat, schedule, webhook.

💬 A message

You, in Slack, Telegram or any chat app you connect. It answers in the same chat.

💓 A heartbeat

A regular check-in: it reads HEARTBEAT.md and messages you only if something needs you. Handy, and a cost setting.

⏰ A schedule

An automation at exact times, like a deployment's cron. Each can run in its own clean session with its own model.

🪝 A webhook

Another app knocks on its door with a secret token: a new form response, a file landing, a payment. It wakes and handles it.

Rule of thumb: a one-off ask is a message; "keep an eye on things" is the heartbeat; an exact time is a schedule; something happening in another app is a webhook.

The one thing no Anthropic surface does

Switch models with one command, and set a fallback.

OpenClaw works with more than 60 providers: Anthropic, OpenAI, Google, xAI, Moonshot (Kimi), OpenRouter, and models running on your own machine. openclaw models set, run in a new VS Code terminal, changes it; /model, typed in a chat with your agent, changes it mid-chat.

🎯 Fit the model to the job

A strong model for judgment calls, a cheap one for routine checks. The same idea as your chain, inside one agent.

🛟 A fallback

If the main model is down or rate-limited, it switches to the next one on your list.

🧪 Test before you trust

Models follow instructions differently. After a switch, test-run it and read what it did.

I run mine on Kimi. Each provider is its own account, its own bill and its own spend limit.

Nobody else is watching this one

You're the security team now.

🧩 Read every skill before you install it

In February 2026, researchers found 341 malicious skills on ClawHub that stole data from Macs. A skill is code with your access. Install only what you or Claude Code have read.

🔒 Keep the Gateway private

Whoever can reach the Gateway controls your agent. By default only your own machine can: keep it that way. openclaw security audit, run in a new VS Code terminal, checks your setup.

🔑 Keys in .env, never in a chat

Not in the chat with Claude, not in the agent's files, not in GitHub.

⬆️ Keep it updated

Security fixes ship often. Early 2026 fixed a bug that let one bad link take over an install.

The Class 5 rules carry over: it drafts, you send, and anything it reads from strangers can try to give it orders.

Before we build · GitHub is where your agent's code lives

The eight words you need for GitHub.

You won't type git commands: Claude Code does. But you'll ask for these by name, so know what each one means.

GitChange tracking. Like Track Changes in Word, but for your whole project.
RepoYour project's folder, tracked by git. Your agent is one repo.
CommitSave. A snapshot on your computer you can always roll back to.
PushSend your saves up to GitHub: a backup with full history.
PullBring the latest version from GitHub down to your computer.
CloneMake a fresh copy of a project from GitHub onto a computer.
BranchA copy where you change things safely. main is the version that runs.
MergeBring a branch's changes into main, once you approve them.

The one people mix up: commit and push both sound like "save." Commit saves on your computer; push sends those saves to GitHub.

Where your changes live

Commit to save, push to back up, merge to make it real.

Your computer Edit and commit

Every change you make, saved as snapshots. Only you have them.

push
GitHub · private Backed up

A copy off your computer, with every snapshot. Lose the laptop, lose nothing.

merge
main The version that runs

Only approved changes get here. In the cloud, the host runs main.

💬

Ask in plain English: "Commit and push this." "What changed since my last commit?" "Something broke: go back to the last commit." Claude Code runs the git commands.

Your repo is private, and .env never leaves your computer: .gitignore tells git to skip it.

Install OpenClaw, with your project folder as its home.

Install OpenClaw with the official installer from docs.openclaw.ai. Before anything else, make this folder a private GitHub repo with a .gitignore that keeps out .env and the agent's memory files. Next, set up my Anthropic API key as an environment variable: open a file in VS Code where I paste the key myself, never in this chat, and make sure the terminal I'll run onboarding in can see it. Check that it works without showing me the key. Then tell me to open a new VS Code terminal in this folder and run: openclaw onboard --classic --workspace "$PWD". When I tell you it's done, check OpenClaw's health, fix anything risky, then commit and push. Keep your answers short.
⌨️ You run onboarding yourself

In a new VS Code terminal. Your key goes in the file Claude opens for you, never into the chat. First screens: read the security notice and say yes, choose QuickStart, and name the agent carefully (the name sticks).

🧭 The screens that matter

How it signs in to your model, your chat app, and the extras to skip. The next two slides walk through them.

During onboarding · the auth method

Sign in with an API key: it's paid, and it's guaranteed.

Onboarding asks how OpenClaw signs in to your model. For Anthropic you'll see three choices, and each one means something different for your bill and your account.

🔑 API key · what we use

A key from the provider's developer console. Pay per use, with a spend cap you set. Works on your computer and on a server.

💻 CLI login · untested

Reuses your Claude Code login, so it runs on your subscription. It failed in our test run. Even when it works, it's computer-only, eats into your plan's limits, and the provider can block it.

🚫 Setup-token · never

Copies a long-lived subscription token into OpenClaw. That's what Anthropic's terms prohibit, and it puts your account at risk.

🔀

Using a different model? The menu will look different, but the same two choices usually exist: a CLI login that borrows your subscription, or an API key billed per use. Same rule: API key.

Next it offers to use the existing ANTHROPIC_API_KEY: choose Yes. That's the key your install prompt set up, kept out of OpenClaw's config. Then let it test AI access: it should pass.

The rest of the wizard

Finish onboarding: connect your chat app, skip the extras.

  • 1. Select channel: pick the chat app you already live in and follow its steps. Telegram is the simplest (a bot from @BotFather). Slack works too, but a work Slack usually needs an admin to approve it. Then message your bot: it replies with a pairing code. Tell Claude Code: "Approve pairing code [code]."
  • 2. Memories found: choose No. It offers to import memories from other AI tools: extra overhead and private context this agent doesn't need.
  • 3. Search provider: skip it. Most options need their own key; you can add web search later.
  • 4. Install missing skill dependencies: skip. Press Space to select Skip for now, then Enter. Step 1 turns those skills off anyway.

When the wizard finishes, tell Claude Code it's done. Your install prompt already told it what to do next.

The control Managed Agents never gave you

Step 1: Clean it out before it costs you on every call.

Open a new VS Code terminal and run openclaw dashboard: the Control UI opens in your browser. In its chat, send /context detail: it shows what every file and skill costs per call. Note the total. Then paste this into Claude Code:

Clean out my fresh OpenClaw install so I can build from a clean slate. Show me each change before you make it. 1) Strip every default example and boilerplate from the workspace files: group chats, emoji reactions, voice, platform formatting, heartbeat check-ins, sample notes. Keep only the red lines and the rule to write memories to files. 2) Turn off every skill it loaded, whether bundled or picked up from other tools on this computer. 3) Turn off every tool except reading, writing and editing its own files, including the shell and web search. Later steps add tools as the agent needs them. 4) Turn the heartbeat off. 5) Restart the gateway, check it's healthy, then commit and push.
📉

Send /context detail in the Control UI chat again and compare. That difference is saved on every message, every schedule and every check-in, for as long as the agent runs.

Rebuild from what works, not a description

Step 2: Pull in your Class 4 and 5 agents as files.

Both links of your chain come over. Download handoff-log.md from your briefing folder into this folder. Then paste this, replacing the highlighted parts with your own:

Use the ant CLI to download two agents from my Claude Console into an export folder: my morning-briefing agent, [its name], with its skill, and my action agent, [its name], which acts on each morning's brief. Rebuild the action agent for OpenClaw: who I am goes in USER.md; its job, the three-section handoff it owes me and its limits go in AGENTS.md; its tone goes in SOUL.md; the standing notes from handoff-log.md go in MEMORY.md. Keep every file short. Don't rebuild the briefing agent: it's the spec for a Python script we'll write later. Then get every app the two agents used working here: connect the same MCP servers, and for each API walk me through getting its key so I paste it into .env myself (create .env first and confirm it's in .gitignore). Test each one by having the agent use it, and turn on any tool it needs. If an app needs a Google sign-in, set it up so the sign-in doesn't expire every week.
📂 The export is your blueprint

Models, system prompts, tools, and the briefing skill. Commit it: it's the record of the version that worked.

🔌 Logins don't come across

Your vault stays in the Console, so each app gets connected again here. Some need a one-time setup, like a Google client for Gmail, Calendar and Drive: Claude Code walks you through it. A "Google hasn't verified this app" warning is expected: it's your own app.

The cost lever and the key rule

Step 3: Set the model, a fallback, and your .env file.

🧠 Models

Tell Claude Code: "Set my main model to [model] and add [model] as a fallback." The main model makes this agent's judgment calls, so don't go cheapest here. Routine jobs can get a cheaper model of their own later.

🔑 The .env file

Step 2 created it, and every key you add later goes there too. Open .env in VS Code and paste each key yourself. Your scripts read keys from it; Claude never sees them in the chat.

✅

Check before every commit: ask Claude "Is anything secret about to be committed?" One habit, and the classic surprise bill can't happen.

Branching, hands-on · your approval gates main

Step 4: Rebuild the brief in Python; you approve the merge.

How branching works: main is the version that runs. A branch is a copy you build and test on, so a broken change never touches what's running. When the test is right and you approve, you merge: the branch's changes join main. Paste this, filling in the highlighted part:

Create a branch called brief-automation. Rebuild my morning brief as a standalone Python script, scripts/brief.py, using the briefing agent and its skill in export/ as the spec. Don't involve OpenClaw. It pulls each source through its API with keys from .env, does all the counting, dates and formatting, makes one call to [a cheap model, e.g. Haiku] for the one judgment (what needs me today), and saves the brief to briefs/, dated. If a source fails, the brief says so. Then register it as a tool my OpenClaw agent can call, named morning_briefing, and check the agent can call it. Run it once, show me today's brief, and review the code. Don't merge until I approve the brief.
🐍 An automation needs no agent

Every step is dictated, so code runs them: same result every run, for almost nothing. The one judgment is a single model call.

🧰 The same script is a tool

The schedule runs it at 7:00 with no agent. Registered as a tool, it's also there when you message "Rerun my brief" midday: the agent calls it instead of redoing the steps.

✋

Nothing merges until you approve it. Read the test brief. Only when it's right, tell Claude Code: "Approved, merge it into main." Every change from now on goes this way: branch, test, your approval, merge.

Your two deployments, rebuilt

Step 5: Schedule the brief at 7:00 and the agent at 7:30.

Schedule scripts/brief.py to run weekdays at 7:00 with this computer's own scheduler, logging to logs/brief.log. Then create an OpenClaw automation for weekdays at 7:30, in its own session: "Handle my morning." It reads today's brief from briefs/ and saves the handoff, dated, to my [Drive / Dropbox] folder so I can open it from anywhere, and sends it to me in my chat app. Then list the next few times each one will run, so I can check both schedules are right.
⏸️ Pause Classes 4 and 5

Once this chain's handoff is right, pause both Managed Agents deployments. Otherwise you get two briefs and double drafts.

💓 Heartbeat stays off

When you want check-ins, turn it on lean: a short HEARTBEAT.md, its own light session, working hours only.

🧰 Test the tool

Message your agent "Rerun my brief." It should call its morning_briefing tool, not redo the steps, and send back a fresh brief.

Same chain as Class 5: an automation handing off to an agent. The automation is plain Python; OpenClaw is for the steps after the brief exists.

Outside events that wake it

A webhook lets another app wake your agent.

You turn on OpenClaw's hooks and it gets an address. Any app that can send a web request can knock on it, with a secret token, and the agent handles what arrives.

📝 A form is submitted

A new brief request from a client: it drafts the kickoff notes.

📂 A file lands

A contract hits your Dropbox: it summarizes it and flags the dates.

⚡ A Zap fires

Anything Zapier or Make can see becomes something your agent can act on.

🌍

Webhooks need an address the internet can reach, and your laptop isn't one. They come with cloud hosting, and the token is a key: it goes in .env.

Explained today, done when you're ready

Render runs your agent from GitHub, laptop open or not.

Render is a hosting service. You sign up with your GitHub account and link your repo; Claude Code adds two small setup files to it. From then on, Render runs your agent around the clock.

🌿 It runs main

Every merge to main redeploys it. That's why every change goes through a branch and a review first.

💾 Pay for a disk

On the free plan, the agent's memory is wiped on every deploy. A paid plan with a disk keeps it.

🔑 Keys go in Render

In Render's environment settings, never in the repo. And it's one more bill to cap.

Once it's live, turn off your laptop's agent: two agents on one bot fight over messages. In the cloud it can take webhooks, and 7:30 runs whether your laptop is open or not.

When it breaks, you and Claude Code are the support team.

🩺 Health

Run these in a new VS Code terminal. First check: is it running? openclaw gateway status. Then openclaw doctor finds broken config, and --fix repairs it. Changed the config? Restart the Gateway, or nothing changes.

📜 What happened

In a new VS Code terminal, openclaw logs --follow streams the log. The Control UI keeps each session's transcript, like Sessions in the Console.

🔍

Describe the symptom and let Claude Code dig: "My 7:30 run didn't come. Check OpenClaw's status and logs and tell me why." Then fix the cause on a branch, like any other change.
